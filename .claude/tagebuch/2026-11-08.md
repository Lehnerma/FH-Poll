## Entscheidungen Admin-Umfragen
- Ein gemeinsames Passwort für alle Umfragen (Firestore `config/pollAccess`, Admin ändert es), getrennt vom Box-Passwort; Prüfung serverseitig in Cloud Functions (`unlockSurvey`, `submitSurvey`, `getSurveyResults`, `setPollPassword`)
- `poll/surveys/<id>` (öffentlich: Titel, `active`, Fragenanzahl) und `poll/content/<id>` (Fragen + Foto-Links, nur Admin/Functions); Antworten schreibt nur die Function, Doppelabgabe-Sperre per Nickname-Schlüssel
- `active=false` heißt „geschlossen“: in der Liste ausgegraut, nicht öffenbar (auch keine Ergebnisse für User); neue Umfragen starten inaktiv
- Frage = Text, optionales Foto (Lupe → Vollbild-Overlay mit `<dialog>`), genau 4 Optionen, eine Auswahl; Fragen jederzeit änderbar (nur für Tippfehler gedacht), kein Umsortieren
- Fotos: Firebase Storage `polls/<umfrage>/<uuid>.<endung>`, JPG/PNG/WebP bis 10 MB, Original, Alt-Text Pflicht; Link nach Passwort, Datei selbst ohne Passwort lesbar
- Ergebnisse: Teilnehmerzahl + je Frage Balken in Prozent, dieselbe Komponente für User (nach Teilnahme) und Admin (jederzeit)
- Passwort bleibt im Arbeitsspeicher wie bei den Boxen (Seite neu laden = erneut eingeben)
- Styling macht Max selbst, Markup hat lesbare BEM-Klassen (`poll-question__*`, `photo-zoom__*`, `survey-results__*`, `poll-editor__*`, `poll-admin-list__*`)
- PRs werden nur erstellt, Max merged selbst

## Stolpersteine beim Einrichten (zum Nachlesen)
- Cloud Storage ist ein eigener Dienst (nicht Firestore): in der Konsole einmal einrichten (Bucket `fh-liane.firebasestorage.app`, `europe-west1`); fehlt er, kommt beim Foto-Upload ein 404 und im Browser eine „CORS“-Meldung
- Ein Deploy mit `--only database,storage,functions` bricht komplett ab, wenn ein Teil scheitert (z. B. Storage ohne Bucket); dann liegen weder neue DB-Rules noch neue Functions online (Symptom: `permission_denied` auf `/poll`)
- Deploy immer aus `main` nach `git pull`, sonst gehen alte Rules/Functions online
- `getSurveyResults` war nach dem Deploy nicht öffentlich aufrufbar (403 ohne CORS-Kopfzeile, Log „request was not authenticated“); Lösung: in Google Cloud → Cloud Run → Dienst `getsurveyresults` → Sicherheit → öffentlichen Zugriff zulassen
- Prüfen aller Functions: Preflight-Anfrage (OPTIONS) liefert 204, bei 403 fehlt die öffentliche Berechtigung
